# Сценарии для защиты

Числа ниже — ручные примеры последовательностей событий, а не результаты экспериментов.

## Happy Flow

Пустой буфер, все принтеры свободны, пакета нет. Заявка 2.1 ставится в конец буфера.
Выбор формирует пакет {2.1} и назначает её принтеру № 1. Ожидание равно нулю.
В момент окончания заявка выходит из системы, принтер освобождается, пакет закрывается.
Если буфер пуст, новый пакет не формируется.

## Полный буфер

N=2, в буфере [2.2,3.1], все принтеры заняты. Приходит 1.1.
Регистрируется генерация и отказ источника 1; буфер остаётся [2.2,3.1].
Приоритет новой заявки не даёт ей права вытеснить старую. Следующее поступление источника всё равно планируется.

## Приоритет пакета и сдвиг

Свободны принтеры № 1 и № 2, текущего пакета нет, буфер [3.1,1.1,2.1,1.2].
Выбирается источник 1; пакет фиксируется как {1.1,1.2}.
1.1 извлекается из позиции 2, буфер становится [3.1,2.1,1.2], назначается принтеру № 1.
1.2 извлекается из позиции 3, буфер становится [3.1,2.1], назначается принтеру № 2.
После окончания 1.1 принтер № 1 ждёт: pending пуст, inFlight={1.2}.
После окончания 1.2 пакет закрывается; следующий пакет — {2.1}.

## Новые заявки не расширяют пакет

Для двух принтеров допустим следующий ручной след. Исходно оба печатают заявки
фиксированного пакета A={2.1,2.2}, буфер пуст, N=2.

| Момент | Событие | Буфер после события | Пакет | Принтер 1 | Принтер 2 |
| --- | --- | --- | --- | --- | --- |
| t₁ | Пришла 2.3 | [2.3] | A, pending=∅, inFlight={2.1,2.2} | 2.1 | 2.2 |
| t₂ | Пришла 1.1 | [2.3,1.1] | A без изменений | 2.1 | 2.2 |
| t₃ | Завершена 2.1 | [2.3,1.1] | A, inFlight={2.2} | свободен | 2.2 |
| t₄ | Пришла 3.1; отказ | [2.3,1.1] | A без изменений | свободен | 2.2 |
| t₅ | Завершена 2.2 | [2.3] | A закрыт; B={1.1} | 1.1 | свободен |
| t₆ | Завершена 1.1 | [] | B закрыт; C={2.3} | 2.3 | свободен |

В t₁ заявка 2.3 имеет тот же источник, что A, но другой ID и не входит в A.
В t₃ нельзя использовать свободный принтер для другого пакета.
В t₄ отказ обусловлен полным буфером и запретом перехода к новому пакету.
В t₅ приоритет источника 1 важнее возраста ожидающей 2.3; Д2П1 выбирает принтер 1.

## Остальные границы

- Все принтеры заняты, буфер свободен: новое задание остаётся WAITING, отказа нет.
- Буфер пуст, принтер освободился: dispatch заканчивается без формирования пустого пакета.
- Один принтер свободен, у пакета есть pending: берётся первый pending ID, очередь сдвигается.
- Несколько принтеров свободны: назначение повторяется, всегда с минимального свободного номера.
- Одинаковое время событий: завершения обрабатываются раньше поступлений.
- После H источники прекращают генерацию, принятые заявки дообслуживаются.

## Инварианты для будущей реализации

1. `0 ≤ len(buffer) ≤ N`; буфер уплотнён, все элементы WAITING.
2. Один ID находится либо в буфере, либо на одном принтере, либо в терминальном состоянии.
3. Все PRINTING принадлежат одному активному пакету; memberIds неизменяемы.
4. Pending и inFlight не пересекаются; их ID принадлежат memberIds.
5. Новая заявка при полном буфере не изменяет старые элементы и пакет.
6. Активный пакет закрывается только при пустых pending и inFlight.
7. На каждый занятый принтер есть ровно одно будущее событие завершения.
8. Для каждого источника `generated = rejected + completed + queued + printing`.
9. При окончании дообслуживания `generated = rejected + completed`.
10. Для обслуженной заявки `arrivalTime ≤ startedAt < completedAt` и `L=W+S`.

Приоритет источников может приводить к долгому ожиданию низкоприоритетного отдела.
Модель не вводит не предусмотренное вариантом старение приоритетов.
