# Симулятор на Java

Вариант 23: ИБ · ИЗ1 · ПЗ2 · Д1ОЗ2 · Д1ОО5 · Д2П1 · Д2Б5 · ОР1 · ОД2.
Основная реализация — Java. Требуется JDK 17 или новее; сторонних библиотек нет.

## Запуск

Windows: откройте run-java.bat в папке проекта. Он найдёт JDK в JAVA_HOME, PATH
или стандартной папке .jdks IntelliJ IDEA, скомпилирует исходники и запустит Main.

IntelliJ IDEA: откройте папку репозитория, выберите Project SDK 17+,
отметьте src как Sources Root, откройте src/Main.java и нажмите Run у main.
В Eclipse или другой Java IDE создайте Java-проект с исходниками из папки src.
Для Java используйте Java IDE, например IntelliJ IDEA; PyCharm предназначен для Python.

Из терминала в папке репозитория:

```sh
javac --release 17 -encoding UTF-8 -d out src/*.java
java -Dfile.encoding=UTF-8 -cp out Main
```

В PowerShell параметр кодировки заключите в кавычки:
`java '-Dfile.encoding=UTF-8' -cp out Main`.

## Параметры

Сначала выберите 1 (пошаговый ОД2) или 2 (автоматический ОР1).
Программа спрашивает число источников, число принтеров, вместимость буфера,
интенсивность λ каждого источника и границы времени печати каждого принтера.
Enter оставляет значение по умолчанию. Дробные числа допускают точку или запятую.
Нулевые, отрицательные и бесконечные параметры отклоняются с повторным запросом.
Seed можно оставить пустым для нового случайного запуска или задать целое число для повторения.
Использованное значение seed всегда печатается.

Приоритет — по возрастанию номера источника. Время в минутах, λ — заявок в минуту.
Поступления случайные по Exp(λ), обслуживание — U(a,b). Учебный фиксированный пример не запускается.
В пошаговом режиме после горизонта источники останавливаются, принятые заявки дообслуживаются.

## Команды

| Команда | Действие |
| --- | --- |
| Enter | Обработать ближайшее событие и показать состояние |
| Число N | Сделать N шагов, показывая каждый |
| j | Показать весь журнал обработанных действий |
| q | Остановить просмотр |

Шаг — ближайшее поступление или завершение печати плюс его последствия в тот же момент.
После шага отображаются журнал действий, текстовая схема системы ОД2, таблицы источников,
буфера по всем позициям, принтеров, календаря и состояние пакета.
Указателей в варианте нет; это явно подписано в выводе.
При совпадении времени завершение имеет приоритет перед поступлением; далее порядок добавления.

Для настроек по умолчанию без опроса: `Main --defaults`.
`Main --defaults --no-pause` печатает все шаги без Enter: это тот же пошаговый просмотр,
а не автоматический расчёт необходимого объёма выборки.

## Автоматический режим ОР1

Выберите 2 в меню или передайте `--auto`. Для запуска без ввода параметров используйте
`java -cp out Main --auto --defaults`.

Первый прогон генерирует ровно 100 заявок. По общей доле отказов p рассчитывается
необходимый объём выборки по методичке: N = ceil(1,643² × (1 − p) / (p × 0,10²)).
Критерий считается выполненным, когда текущая выборка не меньше N и относительное
изменение оценки p между соседними прогонами меньше 10%. Для p = 0 или p = 1
программа увеличивает выборку до следующего прогона. Если заданный лимит уже
достигнут, выводится сообщение, что точность не подтверждена.

Для всех прогонов используются одни параметры и один seed, чтобы сохранить
общее начало случайного потока. После заданного числа поступлений источники
останавливаются, буфер дообслуживается. Загрузка считается от начала моделирования
до конца последнего прогона с учётом дообслуживания. Критерий оценивается для общей
доли отказов по приближённой формуле методички. Таблица по источникам, времена
и загрузка — результаты последнего прогона.

## Структура и инкапсуляция

Восемь классов модели: Simulation, Source, PrintJob, Buffer, Printer, Statistics,
AdmissionDispatcher, SelectionDispatcher. Main отвечает только за ввод и вывод.
Все поля классов модели закрыты (private); неизменяемые ссылки имеют final.
Внешний код получает неизменяемые record-снимки состояния, а не внутренние очереди или заявки.
Изменить пакет или календарь через снимок нельзя.
Вспомогательные record-типы — значения данных, не отдельные активные компоненты СМО.

Диспетчер постановки знает только буфер и статистику. Диспетчер выбора знает буфер и принтеры.
Его списки memberIds/pendingIds/inFlightIds фиксируют состав пакета, ожидающие и печатаемые заявки.
Методы переходов заявки проверяют допустимое состояние.

## Статистика

Создано, отказано, завершено учитываются по источникам и суммарно.
Времена W, S, L и выборочные дисперсии считаются по полностью обслуженным заявкам.
Средние и дисперсии обновляются алгоритмом Уэлфорда без хранения всех времён.
L = W + S, отказам не назначаются нулевые времена обслуживания.
При нуле поступлений вероятность отказа обозначена «—», при менее двух завершениях дисперсия «—».
Загрузка принтера — сумма времени печати / время наблюдения. В ОД2 это максимум
горизонта и последнего завершения, в ОР1 — время окончания прогона.
Средние имеют размерность минут, дисперсии — мин².

## Проверки

```sh
javac --release 17 -encoding UTF-8 -d out src/*.java tests/java/ModelCheck.java
java -cp out ModelCheck
```

Проверяются отказ без вытеснения, Happy Flow, приоритет источников и принтеров,
неизменный состав пакета, FIFO внутри пакета, ожидание границы пакета, сдвиг очереди,
приоритет завершения при равном времени, дообслуживание, повторяемость seed,
неизменяемость снимков и private-поля.
Выполняются 400 случайных конфигураций с проверкой баланса после каждого события.

Для ОР1 отдельно проверяются достижение критерия, точное число поступлений, дообслуживание
и завершение по лимиту при нуле отказов.
