# Правила модели варианта 23

## Основание и трактовка пакетов

Формула взята из строки 23 таблицы вариантов предоставленного пособия:
`ИБ, ИЗ1, ПЗ2, Д1ОЗ2, Д1ОО5, Д2П1, Д2Б5, ОР1, ОД2`.
В таблице пособия встречается запись `Д10З2`/`Д10О5` с цифрой 0;
здесь используется обозначение с буквой О, как в описании дисциплин и авторских документах.

В старом описании Д2Б5 пособия переход к новому пакету связан с исчерпанием заявок пакета
в буфере. Памятка уточняет, что все приборы обслуживают один пакет и следующий формируется
после его полной обработки. Авторские бизнес-домен и маппинг уже используют это уточнение.
Поэтому пакет завершается, только когда нет ни ожидающих, ни обслуживаемых его заявок.
Само формирование возможно и при первом поступлении в изначально свободную систему:
готовность простаивающего принтера разрешает выбор без ожидания искусственного события освобождения.

## Входные параметры и случайность

- n источников, m принтеров, N мест общего буфера; n,m,N ≥ 1.
- λᵢ > 0 — интенсивность независимого пуассоновского потока подразделения i.
- 0 < aⱼ < bⱼ — границы равномерного времени печати на принтере j.
- H > 0 — горизонт генерации, seed — начальное состояние генератора случайных чисел.
- Отделы 1,2,3 — бизнес-пример; модель допускает параметрическое число источников.

Единица модельного времени — минута. λ измеряется в заявках/минуту, a,b,H — в минутах.
Для U∈(0,1): интервал поступления Δtᵢ = −ln(U)/λᵢ.
Для V∈[0,1): длительность печати τⱼ = aⱼ + (bⱼ−aⱼ)V.
Случайные величины независимы; seed позволяет воспроизводить запуски при одинаковых настройках.
Каждый принтер обрабатывает одну заявку целиком, без прерывания и без моделирования поломок.

## События и время

Модель работает по особым событиям. Календарь хранит `ARRIVAL(sourceId)` и
`SERVICE_COMPLETED(printerId, jobId)` с временем и порядковым номером.
Следующее событие выбирается по `(time, priority, sequence)`:
при одинаковом времени сначала завершение печати, затем поступление, затем порядок создания событий.
Событие и все его непосредственные последствия обрабатываются атомарно в один момент времени.
После каждого события делается снимок ОД2 и запись действий в журнал календаря.

При инициализации каждый источник планирует первое поступление.
Каждое поступление всегда планирует следующее, независимо от приёма или отказа текущей заявки.
Поступления с временем > H не добавляются. Принятые заявки дообслуживаются после H.
Календарь пуст после завершения всех принятых заданий; T = max(H, время последнего завершения).
При этом статистика времён относится к полностью обслуженным заявкам, а загрузка — к интервалу [0,T].
Если календарь пуст, а буфер или принтеры непусты, нарушен инвариант планирования.

## Диспетчер постановки

Триггер — событие генерации заявки. `Simulation` сначала регистрирует её в статистике.
`AdmissionDispatcher.admit(job,t)` вызывает `Buffer.isFull()`.
При свободном месте `append(job)` записывает задание в конец (Д1ОЗ2), устанавливая WAITING.
При полном буфере задание получает REJECTED (Д1ОО5), регистрируется отказ, очередь остаётся прежней.
Результат возвращается модели. После принятия модель вызывает `SelectionDispatcher.dispatch(t)`.
Диспетчер постановки имеет ссылки на буфер и статистику; прямой ссылки на принтеры нет.
При занятости всех принтеров принятая заявка ждёт в буфере, дополнительного отказа нет.
При блокировке границей пакета отказ при полном буфере возможен и при простаивающем принтере.

## Диспетчер выбора и фиксированный пакет

Триггеры: успешная запись в буфер и завершение печати.
Перед вызовом после завершения модель освобождает принтер, регистрирует обслуживание
и вызывает `BatchManager.onCompleted(job.id)`; последний завершённый job закрывает пакет.

`dispatch(t)` повторяет следующие действия:

1. `PrinterPool.findFreeByNumber()` перебирает номера от 1. Если свободного принтера нет, возвращается.
2. Если активного пакета нет, `BatchManager.ensureActive(t)` запрашивает
   `Buffer.snapshotHighestPriority()`. Выбирается минимальный sourceId среди очереди;
   копируются ID всех его текущих заявок в порядке поступления (Д2Б5). Пустая очередь завершает выбор.
3. `nextPendingId()` возвращает первый ещё не назначенный ID активного пакета.
   Если такого ID нет, но часть пакета печатается, свободные принтеры ждут.
4. `Buffer.removeById(id)` извлекает заявку и сдвигает последующие элементы (Д1ОЗ2).
   Заявки других источников сохраняют взаимный порядок.
5. `Printer.start(job,t,batchId)` переводит заявку в PRINTING, фиксирует начало и
   генерирует τ по ПЗ2. `BatchManager.onAssigned(id)` переносит ID из pending в inFlight.
6. `Statistics.onStarted(job)` фиксирует ожидание;
   `EventCalendar.schedule(completionEvent)` планирует окончание на t+τ.
7. Повторяется поиск с принтера № 1. Один вызов может назначить несколько заявок.

Пакет содержит неизменяемый `memberIds` и меняющиеся `pendingIds`, `inFlightIds`.
Новые задания, даже от того же источника, остаются вне `memberIds`.
`onCompleted(id)` удаляет ID из inFlight; при пустых pending и inFlight текущий пакет закрывается.
При завершении пакета следующий вызов dispatch выбирает новый источник из текущего буфера.
Принтеры освобождаются независимо, но не переходят на следующий пакет раньше этой границы.
Более приоритетный источник, поступивший во время обслуживания пакета, текущий пакет не прерывает.

## Состояния заявок

`CREATED → WAITING → PRINTING → COMPLETED` либо `CREATED → REJECTED`.
Идентификатор `(sourceId, serial)` уникален. Хранятся arrivalTime, startedAt, completedAt,
batchId (отсутствует до назначения), printerId (отсутствует до назначения).
Ожидающее членство пакета хранится в Batch.memberIds, а не определяется по одному sourceId.

## Статистика и отображение

Для источника i: Gᵢ — сгенерировано, Rᵢ — отказано, Cᵢ — обслужено.
Вероятность отказа Pᵢ = Rᵢ/Gᵢ. В ходе моделирования:
Gᵢ = Rᵢ + Cᵢ + Qᵢ + Bᵢ, где Q — в буфере, B — на принтерах.
После дообслуживания Gᵢ = Rᵢ + Cᵢ.

Для каждой полностью обслуженной заявки:
W = startedAt − arrivalTime; S = completedAt − startedAt; L = completedAt − arrivalTime = W+S.
Средние W,S,L и дисперсии W,S рассчитываются отдельно по источникам и по системе
только для обслуженных заявок. Для дисперсии в отчёте используется выборочная оценка
Σ(x−mean)²/(C−1). При C<2 дисперсия «н/д», при C=0 среднее «н/д», при G=0 P «н/д».
Отказанные заявки не получают фиктивное нулевое время обслуживания.
Загрузка принтера j: Kⱼ = busyTimeⱼ/T. busyTime суммирует фактические интервалы печати.
Средняя загрузка: ΣKⱼ/m. Время ожидания статистически фиксируется при назначении,
времена обслуживания и пребывания — при завершении; повторного учёта нет.

ОР1 показывает сводные таблицы источников, общие результаты и загрузку каждого принтера.
ОД2 показывает схему СМО, модельное время, следующие поступления, содержимое буфера,
членов текущего пакета (pending/inFlight), состояния принтеров, число и процент отказов.
По памятке дополнительно виден календарь и журнал действий: генерация, запись, отказ,
формирование пакета, выборка, назначение, завершение, закрытие пакета.
Указателей и графиков варианта ОР2 в этой модели нет.

## Общая и зонная память

Выбрана общая память: неравномерные потоки отделов используют все свободные места.
Зонная память полезна при гарантированных квотах отделов и изоляции нагрузки;
при этом заявка может получить отказ в своей полной зоне, хотя в другой зоне есть места.
Это отдельное проектное решение с другими условиями заполнения. Здесь зон нет.

## Решения, которые следует сохранить при реализации

Фиксированные ID пакета; FIFO внутри пакета; атомарная обработка событий;
завершение раньше поступления при равных временах; буфер перед назначением;
дообслуживание после H. Эти решения уточняют вариант и делают диаграммы однозначными.
Численные параметры экспериментов и оптимальная конфигурация на этом этапе не выбираются.
