# Как читать диаграмму классов

На схеме восемь классов. Каждый прямоугольник — часть будущей программы:
сверху название, посередине данные, снизу действия (методы).
Минус означает внутренние данные/методы, плюс — методы, которые можно вызывать извне.

| Класс | Простое объяснение |
| --- | --- |
| Модель (Simulation) | Ведёт модельное время и календарь, запускает обработку событий |
| Источник (Source) | Подразделение создаёт новое задание и определяет время следующего |
| Заявка (PrintJob) | Одно задание: номер, подразделение, состояние и временные отметки |
| Буфер (Buffer) | Ограниченная очередь: добавить в конец, получить список, извлечь по ID |
| Диспетчер постановки (AdmissionDispatcher) | Принять задание в буфер либо отказать, если места нет |
| Диспетчер выбора (SelectionDispatcher) | Сформировать фиксированный пакет и выбрать свободные принтеры |
| Принтер (Printer) | Выполнить одну заявку за случайное время U(a,b) |
| Статистика (Statistics) | Учесть поступления, отказы, ожидание и завершение, получить итоговую таблицу |

## Что означают поля

buffer и statistics у диспетчера — ссылки на общие объекты буфера и статистики.
Диспетчеры работают с одним и тем же буфером, отдельных очередей у них нет.
printers — список принтеров. queue — список ожидающих заявок. capacity — вместимость буфера.
currentJob — заявка, которую принтер сейчас печатает, либо отсутствие заявки.

У диспетчера выбора memberIds хранит фиксированный состав пакета;
pendingIds — ещё ожидающие назначения ID; inFlightIds — уже печатаемые ID.
Новое поступление эти списки не расширяет. Когда ожидающих и печатаемых ID не осталось,
пакет закрывается. В следующий раз можно сформировать новый.

В календаре модели хранятся обычные записи времени, типа события и номера источника/принтера.
Это данные, отдельного класса календаря на основной диаграмме нет.

## Как читать метод

append(job: PrintJob): void — добавить в буфер переданную заявку, ничего не возвращать.
isFull(): bool — проверить заполнение; вернуть да или нет.
start(job,t): float — начать печать заявки в момент t, вернуть время окончания.
dispatch(t): List<record> — назначить доступные задания пакета, вернуть записи новых завершений
для календаря модели. Если назначений нет, возвращается пустой список.

Типы: int — целое число; float — число с дробной частью; string — строка;
bool — да/нет; List — список; Set — множество; Map — значения по ключам;
знак ? — значение может отсутствовать. record и table — запись и таблица данных.
Методы доступа к закрытым данным на схеме опущены для читаемости; поля не становятся публичными.

## Что означают связи

Сплошная стрелка показывает, что класс хранит ссылку и обращается к другому объекту.
Чёрный ромб у модели обозначает, что она создаёт и содержит свои компоненты.
Белый ромб у буфера означает хранение заявок: после извлечения заявка продолжает существовать.
Пунктир от источника к заявке означает создание заявки.
0..N — в буфере от нуля до N заявок; 0..1 — принтер печатает не более одной;
1..m — список принтеров системы.

Для объяснения: источник создаёт заявку, диспетчер постановки помещает её в буфер,
диспетчер выбора передаёт принтеру, статистика учитывает результат, модель управляет событиями.

## Соответствие дополнительным диаграммам

Основная схема классов задаёт восемь классов будущей реализации.
В дополнительных подробных материалах старые обозначения показывают функциональные роли:
BatchManager и Batch — логика пакета внутри диспетчера выбора;
PrinterPool — список принтеров и поиск свободного у него же;
EventCalendar — календарь внутри модели. Они не требуют дополнительных классов.
